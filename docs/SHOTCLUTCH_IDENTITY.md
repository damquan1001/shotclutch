# ShotClutch identity and project compatibility

Post-M0 identity cleanup branch: codex/shotclutch-identity. Application/CLI binaries stay shotclutch and shotclutch-cli; version 0.13.0 and existing ShotClutch installer/data identities are retained. Workspace packages/imports now use shotclutch-* / shotclutch_*.

New files and snapshots use .scproj and shotclutch.project; the M0 identity baseline used payload schema version 15. M1 schema v16 added opaque versioned extensions; schema v17 adds canonical document identity, revision, retained history and checksummed snapshots. Historical v15/v16 migrations remain supported. Supported .fcproj and filmcraft.project documents still load, including historical fixtures. An opened legacy project requires Save As to a new .scproj destination. Its original stays untouched. CLI --save on a legacy project fails with instructions to use --save-as. A different existing Save As destination is never silently overwritten. No legacy project is converted merely by opening it. New envelopes use a distinct identifier and are not promised to open in upstream readers.

Canonical environment controls are SHOTCLUTCH_*. Runtime readers accept corresponding FILMCRAFT_* fallback aliases; a present canonical value, including an empty value, takes precedence. Non-Unicode canonical values are not hidden by a legacy fallback. Environment lookup is centralized in the std-only shotclutch-env leaf crate. No legacy Cargo package wrappers are introduced.

Desktop automation uses --control / SHOTCLUTCH_CONTROL_PORT plus a private SHOTCLUTCH_CONTROL_TOKEN (64 random hex characters). Bindings remain localhost; new control settings override inherited aliases. Do not store tokens in reports. Browser automation uses window.shotclutch; window.filmcraft is a thin reference to the same object. Diagnostic globals follow the same rule: shotclutchLoad/shotclutchFatal are canonical and their inherited aliases point to the same objects. MCP resources list shotclutch://document and shotclutch://commands; old scheme identifiers remain readable aliases. Command IDs do not change.

Original ShotClutch icon artwork is used across platform packages, web favicon and installer background. Generate committed variants with scripts/generate-icons.py using PySide6, Pillow >=12, ds_store==1.3.3 and mac_alias==2.2.3; normal builds do not need those tools. Installer text loads the retained Inter font explicitly. The Finder layout uses the ShotClutch volume/application names and contains no local volume/user metadata. The identity guard checks binary packaging assets, including UTF-16 names. On this host the bundled runtime Python works; the unrelated system Python has a Qt DLL conflict. No third-party application artwork is reattributed as ours.

Required copyright/license notices, retained-asset authorship, genuine upstream source URLs, original fixtures and archived M0/upstream reports remain truthful. This is legal/provenance retention, not product branding. The original M0 baseline and reports are not regenerated or renamed. See NOTICE, LICENSE-MIT, LICENSE-APACHE and ATTRIBUTION.md for retained notices. No user data or installed application is moved or modified by this change.

Qualification passed for implementation a6229303: complete Windows/Linux/macOS CI, unsigned Windows packages, hosted installation/uninstallation and the exact packaged desktop workflow. See [the validation record](identity/EVIDENCE.md) for commands, hashes, repairs and scope limits. IDENTITY-001 is complete; M0 evidence remains unchanged.
