## Native media

[qualification.json](native-media-20261105/qualification.json) records the bounded corpus,
machine/driver inventory, build/tool versions, source/oracle/executable digests and mode-report
digests. [Software](native-media-20261105/software.json), [Auto](native-media-20261105/auto.json)
and [forced fallback](native-media-20261105/forced-fallback.json) each passed all nine cases.
Every verified video-frame hash matches across the three modes. Forced fallback injects a fault
into a software-backed decoder inside the real HybridDecoder; it is not physical GPU-loss evidence.
Auto separately recorded 256 hardware pictures, including extra cold-seek/replay decoding.

The three native mode reports are unchanged copies of the final local outputs. Their report
digests and all recorded source/lockfile digests were checked before retention. Qualification/UI
summaries normalize only line endings to LF; no values change. `baseRevision` and `dirty:true`
describe the build before its local commit; the explicit source-file digests identify the changed
native implementation. GPU inventory does not identify the active adapter for each session.
The local attributes preserve LF report bytes across Git checkouts, so the retained mode-report
digests remain verifiable on Windows.

Reproduce locally with installed ffmpeg/ffprobe:

```text
python scripts/m1/qualify-media.py --out target/m1/<new-directory>
```

The script builds with locked/offline Cargo, generates every required source/reference, and fails
on missing tools, cases, decode errors, timestamp/frame/PCM mismatches or failed mode processes.
Generated media, large raw RGBA/PCM references and binaries stay under ignored `target/`; they are
not hosted CI inputs or runtime dependencies. [DEC-006](../DEC-006_NATIVE_MEDIA.md) defines the
qualified subset, thresholds, exact clock fixes and limits. Short query timings are not sustained
playback, compositor or export measurements.

## Bounded desktop smoke

[smoke.json](ui-smoke-20261105/smoke.json) records the desktop binary/source/saved-project digests
and the independently reopened split/undo/redo track states. The fixture is the synthetic VFR
phone clip generated by the existing CLI workflow tests, copied to private local test media.
The editor used a separate data/recovery directory; ordinary user projects/preferences were not
changed. The [clean final screenshot](ui-smoke-20261105/editor-after-redo.png) shows source frame 5
and the saved video/audio cut after redo.

Verified actions: Shift+Right seeks five frames; the visible Sequence menu's Add Edit to All
Tracks splits at frame 5; Ctrl+S saves; Ctrl+Z undoes; Ctrl+Shift+Z redoes. Separate headless CLI
processes reopened each saved result and checked clip counts, exact boundaries/source offsets
and linked groups. A global shortcut intercepted Ctrl+Shift+K, so the split was applied through
the editor menu instead. The test editor exited normally after saving.

This smoke does not complete the whole manual editing/accessibility workflow. The PC remained
network connected. Neither these reports nor headless frame/sample checks establish a disconnected
no-egress run, physical device-clock A/V timing, long-form underruns/drift, storage-crash behavior,
or wider performance/format promises. No hosted Actions, push, release or GitHub settings change
was used for this continuation.
